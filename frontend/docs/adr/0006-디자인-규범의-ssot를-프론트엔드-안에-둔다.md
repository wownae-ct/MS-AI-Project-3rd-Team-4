## 맥락

화면 6개 스펙이 도착해 구현 착수가 가능해졌다([../mockups/README.md](../mockups/README.md)). 착수 전 규범을 점검하다 **두 가지가 드러났다.**

### 1. 규범의 값 출처가 프론트엔드 밖에 있다

`src/shared/ui/theme.css`, `src/shared/ui/README.md`, `scripts/check-bundle-budget.mjs`, 프리미티브 주석 여러 곳이 **프론트엔드 브랜치에서 열 수도 고칠 수도 없는 문서**를 SSOT로 가리키고 있다. 전수 조사 결과 **`frontend/` 안에서 정정 대상인 참조가 45건 / 12파일**이다(ADR 20건과 목업 사본 2건은 역사 기록·원본 사본이라 제외).

결과는 두 가지다.
- **규범을 고칠 절차가 성립하지 않는다.** *"값을 바꾸려면 원본 문서를 먼저 고친다"* 인데, 그 문서를 이 브랜치에서 고칠 수 없다
- **작업 범위가 새어 나간다.** 규범을 확인하려면 프론트엔드 밖을 봐야 하고, 실제로 그렇게 됐다

### 2. 「구조로 강제된다」고 적힌 것 중 여러 개가 강제되지 않는다

`theme.css`가 실제로 폐기한 Tailwind 네임스페이스는 **`--color` 하나뿐**이다. 그런데 문서·주석·**스타일가이드 화면**은 여러 규범이 구조로 강제된다고 말한다.

| 서술 | 위치 | 실측 |
|---|---|---|
| *"팔레트 밖 색은 유틸리티 자체가 생성되지 않는다"* | 4곳 (**2곳은 화면 렌더**) | **절반만 맞다.** 임의값 `bg-[#77354F]`는 그대로 컴파일된다 |
| *"라운드 sm / md / pill"* (3단계로 읽힌다) | `src/shared/ui/README.md:28` | Tailwind 기본 `--radius-*` **8단계가 살아 있다.** `rounded-2xl`(16px) · `rounded-4xl`(32px)도 생성된다 |
| *"그림자 토큰을 두지 않는다"* | `theme.css:74-75` | **틀렸다.** 기본 그림자 토큰 **22개**(`shadow` 8 · `drop-shadow` 6 · `inset-shadow` 3 · `text-shadow` 5)가 살아 있다 |

게다가 그림자 금지 게이트에 **사각지대**가 있다. 정규식이 `box-shadow:` 하나만 찾는데 `text-shadow-*`는 `text-shadow:`로 나가 매치되지 않는다.

**`drop-shadow-*`의 사각지대는 더 깊다.** 설치본을 컴파일해 확인한 결과 Tailwind 4.3.3은 `filter:`에 `drop-shadow(…)`를 **넣지 않는다** — `--tw-drop-shadow-size: drop-shadow(…)`라는 **커스텀 속성**에 넣고 `filter:`에는 `var(--tw-drop-shadow,)`만 둔다. 즉 *"`filter:` 안에서 `drop-shadow(`를 찾는다"* 는 검사는 **한 건도 매치하지 못한다.** 속성 이름으로 추정하면 이렇게 조용히 무동작인 게이트가 만들어진다.

그리고 **`ring-*`는 어느 네임스페이스 폐기로도 막히지 않는다**(아래 실측표). `ring-<width>`는 `box-shadow`를 내지만 `ring-<color>` · `ring-inset` · `inset-ring-*`은 `--tw-ring-color` 같은 **커스텀 속성만** 내므로 값 검사로도 잡히지 않는다.

**두 문제는 같은 뿌리다** — 「의도를 문서에 적고 구조로 강제했다고 믿는 것」. 이 저장소가 `.env`의 `NODE_ENV`, oxlint `plugins` 대체(97→80), 경로 별칭 이중 정의에서 반복해 부딪힌 사고 클래스와 같다.

## 결정

요지는 넷이다.

### 1. 규범의 SSOT를 `frontend/docs/design/`에 둔다

값의 **소재지**는 `src/shared/ui/theme.css`(Tailwind `@theme`), **근거와 결정**은 `frontend/docs/design/`. 값을 바꿀 때는 문서를 먼저 고치고 `theme.css`를 맞춘다.

**자립 원칙** — 이 문서군은 `frontend/` 밖을 규범의 근거로 참조하지 않는다. 프론트엔드 브랜치에서 열 수 없거나 고칠 수 없는 것에 규범을 의존시키면 그 규범은 유지될 수 없다. 외부 **기술 문서**(W3C · MDN · Tailwind · Base UI · KRDS 등)는 근거로 인용하되 **URL과 확인 등급**을 함께 적는다.

**ADR과 목업 사본은 고치지 않는다.** ADR은 그 시점의 결정 기록이고(`README.md` §절차 — *"뒤집을 때는 삭제하지 않고 상태: 폐기"*), 사후 편집하면 기록이 위조된다. 목업은 원본의 사본이며 머리말이 이미 출처를 밝힌다.

### 2. 규범이 금지한 네임스페이스를 폐기한다

```css
--radius-*: initial;          /* 후 sm 8 / md 10 / lg 16 / pill 999 4단계 */
--shadow-*: initial;
--drop-shadow-*: initial;
--inset-shadow-*: initial;
--text-shadow-*: initial;
```

**폐기는 「규범이 금지한 것」에만 적용한다.** `--text-*` · `--font-*` · `--spacing` · `--breakpoint-*` 등은 **기본을 쓰기로 이미 결정한 항목**(0003 §3)이라 유지한다. 전수 감사와 사유는 [../design/namespaces.md](../design/namespaces.md).

**폐기가 실제로 막는 범위는 컴파일로 확인했다**(아래 실측표). 그림자 4계열과 `rounded-3xl` 등 기본 8단계는 폐기만으로 사라진다. **막지 못하는 것** — `ring-*` 4종(폐기와 무관한 네임스페이스) · 임의값(`bg-[#hex]`) · `rounded-full`(`calc(infinity * 1px)`, `staticValues`) · `rounded-none`(`0` — 토큰 밖 값이 아니라 무해). 앞 셋이 게이트가 맡아야 할 몫이다. (`rounded-full`은 승인 직후 폐기 계약 테스트가 「사라진다」는 초기 기록을 반증해 정정했다.)

이는 **0003 §3의 "스케일은 Tailwind 기본을 따르고 정한 것만 덮어쓴다"를 라운드·그림자에 한해 바꾸는 결정**이다. 0003이 그렇게 정한 것은 당시 필요가 없었기 때문이고, 지금은 "3단계"·"토큰 없음"이라는 서술이 사실이 아니게 만드는 원인이 됐다.

### 3. 빌드 게이트를 **정규식이 아니라 CSS 파서로** 다시 만든다

**정규식을 버린다.** 위 사각지대 두 건(`drop-shadow`가 커스텀 속성으로 나감 · `ring` 색이 커스텀 속성만 냄)은 정규식의 실수가 아니라 **한계**다. 속성 이름 문자열을 찾는 방식으로는 「값이 무엇인가」를 알 수 없고, 부정 전방탐색으로 값을 배제하려 하면 백트래킹 우회가 생긴다(실제로 커밋 `3d518c6`이 그 오탐을 고쳤다).

`lightningcss`의 `Declaration` visitor를 쓴다. **새 의존성이 아니다** — `vite`(`^1.33.0`)와 `@tailwindcss/node`(`1.32.0`)가 이미 선언한 정식 의존이고 Vite 파이프라인이 쓰는 것과 같은 파서다. 다만 **전이 의존을 암묵적으로 쓰지 않는다** — `package.json`의 `devDependencies`에 명시한다(이 저장소가 별칭·Node 버전에서 거부해 온 이중 출처·암묵 의존 패턴).

`scripts/check-bundle-budget.mjs`를 순수 모듈로 쪼갠다 — `scripts/lib/css-norms.mjs`(산출 CSS → 위반)와 `scripts/lib/source-norms.mjs`(소스 → 위반). **쪼개는 이유는 테스트 가능성이다.** 위 오탐 수정이 재발할 뻔한 근본 원인은 *수정 사유가 주석으로만 보호됐다*는 것이다.

| 검사 | 내용 |
|---|---|
| **그림자·링** | ① `box-shadow`·`text-shadow` 선언의 **값**이 `none`이 아닌 것 — 파서가 값을 주므로 백트래킹 오탐이 **구조적으로 불가능**하다 ② **어떤 값에든** `drop-shadow(` 함수 토큰이 나타나는 것(커스텀 속성 값 포함) ③ `--tw-shadow` · `--tw-drop-shadow*` · `--tw-text-shadow*` · `--tw-ring-shadow` · `--tw-inset-ring-shadow` · `--tw-ring-color` · `--tw-inset-ring-color` 선언이 **초기값 이외**의 값을 갖는 것 ← 정규식으로는 닫지 못하던 `ring` 구멍 |
| **팔레트 밖 색** | 화이트리스트를 **`theme.css`에서 읽고**(주석 제거 후 파싱) 파싱된 색 값과 대조한다 |
| **라운드 값** | `border-radius` 값이 `--radius-*` + `0` 화이트리스트 안인가. 파서가 `calc(infinity * 1px)`와 `.25rem`을 구분해 준다 |
| **폐기 유지** | `theme.css`에 필수 폐기 선언 6종이 있는지 확인. 하나라도 빠지면 실패 |
| **소스측** | `src/**/*.{ts,tsx}`에서 색 임의값(`bg-[#…]` 등)과 `ring-` 클래스 토큰을 **`file:line`과 함께** 보고한다 |

**소스측 검사를 린트가 아니라 스크립트에 두는 이유** — oxlint에는 `no-restricted-imports`·`no-restricted-properties`는 있으나 **`no-restricted-syntax`가 없다**(공식 규칙 목록 확인). 그리고 산출 CSS만 보면 알려 줄 수 있는 위치가 `.bg-\[\#77354F\]`라는 셀렉터뿐이라 고칠 곳을 못 찾는다.

**임의값을 Tailwind 설정으로 막을 수는 없다.** 공식 문서가 임의값을 제한하는 설정을 제공하지 않고, `@utility`는 추가만 하며 내장 유틸리티를 덮어쓰지 못한다. **게이트가 유일한 수단이다.**

**우회 플래그를 만들지 않는다.** 새 색이 필요하면 `decisions.md` → `theme.css` 순서로 넣으면 화이트리스트가 자동으로 따라온다.
**알려진 한계를 매 실행 출력한다** — `dist/assets/` 비재귀 스캔 · `dist/index.html`의 인라인 `<style>` 미검사 · 팔레트 색의 임의값 하드코딩은 통과.

### 4. 「구조로 강제한다」고 쓰려면 주입 시험을 통과한 뒤에 쓴다

이 저장소가 이미 쓰던 원칙(*"새 게이트가 위반을 실제로 잡는 것을 증명하기 전에 기존 게이트를 걷어내지 않는다"*)을 **문서 서술에도 적용한다.** 확인 전에는 "의도"라고 쓴다.

### 실측 검증 (2026-08-21)

| 항목 | 방법 | 결과 |
|---|---|---|
| 임의값이 팔레트 폐기를 우회한다 | `tailwindcss/dist/lib.js`의 `functional("bg")` — `value.kind === "arbitrary"` 분기가 테마 조회보다 **먼저 반환** | 확정 |
| 이 저장소에서 임의값이 실제로 컴파일된다 | 산출 CSS의 `padding-inline:11px` (`Button.tsx:27`의 `px-[11px]`) | 확정 |
| `--radius-*` 8단계 생존 | `tailwindcss/theme.css` 전수 | xs 2 / sm 4 / md 6 / lg 8 / xl 12 / 2xl 16 / 3xl 24 / 4xl 32 px |
| 그림자 22토큰 생존 | 같은 파일 전수 | `shadow` 8 · `drop-shadow` 6 · `inset-shadow` 3 · `text-shadow` 5 |
| 게이트 사각지대 | 정규식 `/box-shadow\s*:…/` 문자열 대조 | `text-shadow:` 에 매치 불가. `drop-shadow`는 아래 행 |
| **`drop-shadow-*` 방출 형태** | `tailwindcss` `compile()` 로 직접 컴파일 | `--tw-drop-shadow-size: drop-shadow(…)` + `filter: … var(--tw-drop-shadow,)`. **`filter:` 안에 `drop-shadow(` 없음** — 속성 이름 기반 검사는 무동작 |
| **폐기 5종 적용 후 생성 여부** | `compile()` 에 실제 `theme.css` 를 넣고 후보 컴파일 (폐기 계약 테스트가 상시 재확인) | 사라짐: `rounded-3xl`·`2xl`·`xl`·`xs` · `shadow` · `shadow-md` · `inset-shadow-sm` · `drop-shadow` · `drop-shadow-md` · `text-shadow-sm` / **살아남음: `ring` · `ring-2` · `ring-primary` · `inset-ring-2` · `bg-[#77354F]` · `rounded-none` · `rounded-full`**(초기 기록은 「사라짐」이었으나 테스트가 반증) |
| 폐기 대상 유틸리티 현재 사용처 | `src/**/*.tsx` grep | `rounded-sm` 9 · `rounded-md` 4 · `rounded-pill` 3 — **폐기 대상 0건** |
| 산출 CSS 색 리터럴 | 전수 | hex 8종 전부 팔레트 내 · named/함수형은 Preflight 프로브 |
| `ring`이 `box-shadow`를 낸다 | `functional("ring")` | **폭 유틸리티만** 확정. `ring-<color>` · `ring-inset` · `inset-ring-*`는 `--tw-ring-color` 등 커스텀 속성만 냄. v4 기본 두께 1px · 기본 색 `currentcolor` |
| **산문이 유틸리티를 만든다** | 산출 CSS 셀렉터 ↔ 소스 토큰 전수 대조 | `.p-5` · `.p-6`는 `src/shared/ui/README.md`의 표 문구에서만 발견 · `.rounded{border-radius:.25rem}`(**토큰 밖 4px**)도 산출물에 실재. `@source "../../"`가 `.md`까지 스캔하고 Tailwind는 주석을 구분하지 않는 평문 스캐너이기 때문 |

## 결과

**쉬워지는 것**

- 규범 개정 절차가 **이 브랜치 안에서 완결된다** — 문서를 고치고 `theme.css`를 맞추고 게이트가 검증한다
- 「팔레트 밖 색 금지」·「그림자 없음」·「라운드 4단계」가 **문장이 아니라 상태**가 된다
- 새 색·새 라운드가 필요할 때 **어디를 고쳐야 하는지가 한 곳**이다
- 폐기 대상 사용처가 지금 0건이라 **화면 구현 전인 지금이 가장 싸다**

**어려워지는 것**

- 예외를 쓰려면 임의값(`rounded-[12px]`)이 필요하고, 그건 리뷰에서 눈에 띈다 — **의도한 마찰이다**
- 게이트가 `npm run build` 체인 안이라 **이후 모든 프론트 PR에 적용된다.** 오탐 시 빌드가 막히므로 위반 값과 주변 문맥을 함께 출력하고, 검사 범위와 한계를 매 실행 출력한다
- 규범 문서가 늘어난다 — 대신 `theme.css` 주석에 근거를 몰아넣지 않아도 된다

**뒤집으려면**

- 폐기 5줄 + 게이트 모듈 2개 + `REQUIRED_RETIREMENTS` 목록 + `lightningcss` devDependency 한 줄을 되돌린다(커밋 revert). 앱 번들 영향은 없다
- 단 그 사이 폐기 대상 유틸리티나 새 토큰을 쓴 코드가 있으면 함께 정리해야 한다
- SSOT 이관 자체를 뒤집으려면 `frontend/docs/design/`을 폐기하고 참조 45건을 되돌린다 — **비용이 크다.** 그래서 이 ADR로 근거를 남긴다

**검증 방법**

**게이트 검증은 수동 주입이 아니라 vitest가 상시 돌린다** — 체커가 순수 모듈이므로 합성 CSS 픽스처로 양성·음성·경계를 고정하고, `tailwindcss` `compile()`에 실제 `theme.css`를 넣어 폐기 계약(사라져야 할 것이 사라지고, 살아남는 것은 살아남는다고 **둘 다** 단언)을 고정한다. 전체 목록은 [../design/implementation-plan.md](../design/implementation-plan.md) §검증.

빌드 사이클이 필요한 것만 남긴다:

1. **금지 게이트 실동작** — 폐기 적용 **전**에 `shadow-md` · `drop-shadow-md` · `ring-primary` · `bg-[#77354F]`를 소스에 주입 → 각각 **exit 1** + 소스 `file:line` 출력. 폐기 뒤에 하면 유틸리티가 생성되지 않아 게이트를 검증할 수 없다
2. `theme.css`에서 `--radius-*: initial` 임시 삭제 → **exit 1** (재발 방지 동작 확인)
3. `npx oxlint --format=json .` 의 `number_of_rules` = **297** 유지
4. 주입 없이 빌드 → 오탐 **0건** (팔레트 밖 · 그림자 · 라운드 · `prefers-color-scheme`)

> ⚠️ **하지 말 것**: `theme.css`에서 색 한 줄을 지우고 그 색이 위반으로 잡히는지 보는 시험. 색을 지우면 그 색을 쓰는 유틸리티도 생성되지 않아 산출 CSS에서 **함께 사라진다.** 시험이 성립하지 않는다.
