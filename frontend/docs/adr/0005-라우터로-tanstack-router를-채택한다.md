- 상태: **제안** — 구현 완료. 승인 조건 **R1~R6 충족**, **R7(CLS·LCP 실측)만 남았다**(아래 「승인 조건」 표).
- 날짜: 2026-08-22(작성 · 구현 · R1~R6 측정) · 결정자: — · 합의 채널: —

> **왜 아직 「승인」이 아닌가** — R7 이 미측정이고, 상태를 바꾸는 것은 결정자의 행위다(CLAUDE.md §5.8-4).

- 선행 의존: [0003](0003-스타일링-엔진으로-tailwind-css-v4를-채택한다.md)(번들 예산 게이트가 이 결정의 제약이다) · [0004](0004-접근성-프리미티브로-base-ui를-채택한다.md)(*"쓸 곳이 확정되지 않은 것을 미리 만들지 않는다"* 원칙)
- 관련 문서: [../design/layout.md](../design/layout.md)(앱 셸·라우트 표·내비 접근성 계약) · [../design/implementation-plan.md](../design/implementation-plan.md)

## 맥락

화면 6개(S1~S6)의 시각 스펙이 도착했고([../mockups/](../mockups/README.md)), 앱 셸·라우트 표·내비게이션 접근성은 [layout.md](../design/layout.md)에 **계약으로 확정**돼 있다. 디자인 규범 구현도 끝났다(ADR 0006 · C1~C10). 남은 선행 조건은 **라우터 하나**다.

### 왜 `useState` 로는 안 되는가

`App.tsx`가 이미 그 이유를 적어 두었다 — *"useState 페이즈 전환으로는 공유 가능한 URL 을 만들 수 없다."* 구체적으로 깨지는 것:

- **뒤로가기·새로고침** — 온보딩 6단계 중간에서 새로고침하면 처음으로 돌아간다
- **링크 공유** — 「스드메 카테고리 상세」를 보내려면 URL이 있어야 한다
- **앱 셸의 활성 표시** — 탭바·사이드바의 `aria-current="page"`는 *"지금 어느 라우트인가"* 를 알아야 계산된다. layout.md의 셸 규칙(`tabHome active = (screen === 'dashboard' || screen === 'category')`)이 그 값을 요구한다
- **포커스 이동** — `Page`의 `<h1 tabIndex={-1}>` + `focusOnMount`는 *"화면이 바뀌었다"* 는 사건이 있어야 의미가 있다. 지금은 죽은 코드다

### 제약 — 번들 예산

현재 JS gzip **76,837 B / 한도 92,000 B**, 여유 **15,163 B**. 그리고 이 저장소의 Slow 4G 실측이 한 가지를 더 말한다:

> **폰트 요청은 CSS가 아니라 JS 번들 뒤에 직렬화된다.** JS 완료 1,718 ms → **19 ms** 만에 폰트 요청. (`../architecture/toolchain.md` §8.2)

폰트는 첫 방문 전송의 **81%**(408,988 B)이고 LCP 경로다. 즉 **JS가 커지면 폰트 시작이 그만큼 밀린다.** 라우터 선택에서 번들 크기는 "예산 숫자" 문제가 아니라 **LCP 문제**다.

## 검토한 대안

### 실측 방법

`esbuild --bundle --minify --format=esm --target=chrome111`, `react`/`react-dom` 외부화, **우리가 실제로 쓸 API 부분집합만** import 한 뒤 `gzip -9`. bundlephobia의 barrel import 상한(59k/39k/2.6k)이 아니라 **tree-shaking 이후의 값**이다.

| 후보 | 버전 | gzip (최소 사용면) | gzip (실사용면) | 주간 다운로드 | 최근 릴리스 | peer / engines |
|---|---|---|---|---|---|---|
| `react-router` | 8.3.0 | — | **31,404 B** | 43,605,841 | 2026-08-18 | react ≥19.2.7 · node ≥22.22 |
| **`@tanstack/react-router`** | 1.170.31 | **28,346 B** | **28,687 B** | 20,110,532 | 2026-08-19 | react ≥18 · node ≥20.19 |
| `wouter` | 3.10.0 | — | **3,151 B** | 2,185,299 | 2026-05-21 | react ≥16.8 |

**TanStack Router는 트리셰이킹으로 줄지 않는다** — 최소 사용면과 실사용면의 차이가 341 B다. 코어가 통짜라는 뜻이고, 이 값이 그대로 초기 청크에 들어간다.

### `wouter`를 기각한 진짜 이유 — 이 저장소의 방향과 반대다

번들만 보면 wouter가 압도적이다. 그런데 이 저장소는 직전 작업(ADR 0006)에서 **「문서로 적힌 규범」을 「빌드가 강제하는 상태」로** 전부 옮겼다. 팔레트·라운드·그림자가 이제 문장이 아니라 게이트다.

내비게이션은 **아직 아무도 강제하지 않는 마지막 영역**이다. wouter의 `useParams<{ id: string }>()`는 그 타입이 실제 라우트와 맞는지 **아무도 검사하지 않는다** — 정확히 이 저장소가 반복해 손해 본 *"적어 두었으니 지켜지겠지"* 패턴이다. TanStack Router의 타입 안전 라우트는 같은 문제를 컴파일러가 잡게 만든다.

**그 일관성에 28 kB를 지불할 가치가 있는가** — 이 ADR이 답해야 할 질문이고, 답은 「조건부로 그렇다」이다.

## 결정

### 1. `@tanstack/react-router` 1.170.31 을 **정확 핀**으로 채택한다

정확 핀인 이유는 `tailwindcss`·`@base-ui/react`와 같다 — 라우트 타입 추론과 코드 스플리팅 동작에 우리 코드가 의존하므로, 올리는 것은 의도적이어야 하고 올릴 때 테스트가 먼저 알려야 한다.

### 2. **코드 기반 라우팅**을 쓴다 — Vite 플러그인도 생성 파일도 두지 않는다

파일 기반 라우팅은 `routeTree.gen.ts`를 생성한다. **[ADR 0003](0003-스타일링-엔진으로-tailwind-css-v4를-채택한다.md)이 Panda CSS를 기각한 사유가 정확히 이것이다** — 생성 디렉터리가 `.gitignore`·`ignorePatterns`·`noUnusedLocals`와 3중으로 마찰한다. 같은 마찰을 라우터로 다시 들여오지 않는다.

`createRootRoute` · `createRoute` · `createRouter` 는 플러그인 없이 동작하고 **타입 안전은 그대로 유지된다**(설치본 확인). 라우트가 6개뿐이라 코드 기반의 수동 배선 비용도 작다.

### 3. **라우트 단위 코드 스플리팅을 같은 커밋에 넣는다**

이것이 이 결정의 **조건**이다. 라우터 코어 28.3 kB를 그냥 얹으면 초기 JS가 +37%가 되고 폰트 시작이 밀린다. 대신:

- 초기 청크 = 라우터 코어 + 앱 셸 + **첫 화면 하나**
- 나머지 5화면 = `lazyRouteComponent` 로 분할

**분할 없이 도입하지 않는다.** 게이트도 함께 바꾼다 — 지금 `jsGzip`(총합)과 `jsChunkGzip`(최대 단일 청크)이 같은 값인 것은 청크가 1개라서였고, 분할이 들어와야 비로소 두 지표가 갈린다. **사용자가 실제로 기다리는 것은 초기 청크**이므로 그쪽을 조인다.

**재설정 결과(2026-08-22 적용)** — 두 지표의 역할이 갈렸다:

| 지표 | 한도 | 실측 | 역할 |
|---|---|---|---|
| `jsChunkGzip` (초기 청크) | **92,000 — 올리지 않았다** | 88,847 (97%) | 사용자가 실제로 기다리는 바이트. 조이는 쪽 |
| `jsGzip` (전 청크 합) | 92,000 → **112,000** | 108,099 (97%) | 앱 전체 크기 가드. 한 번에 전송되지 않는다 |

합계 한도를 올린 이유는 관대해지려는 게 아니라 **지표가 뒤집힌 유인을 만들고 있었기 때문**이다 —
청크가 1개일 때 만든 92,000 을 분할된 앱의 합계에 그대로 적용하면 *화면을 lazy 로 잘 나눌수록 게이트에 걸린다.*

초기 청크 여유는 **3,153 B** 뿐이다. **첫 화면(S2 대시보드)을 구현하면 이 게이트가 먼저 걸린다** — 의도한 마찰이다.
그때 필요한 것은 한도를 올리는 게 아니라 첫 화면이 정말 초기 청크에 있어야 하는지 다시 묻는 것이다.

### 4. 앱 셸은 [layout.md](../design/layout.md) 계약을 그대로 구현한다

`<nav>` 랜드마크 + 링크 리스트 · `role="tablist"` 금지 · `aria-current="page"` 하나만 · 복수 `<nav>`에 고유 `aria-label` · **단일 DOM + CSS 재배치**(DOM 이중화 금지). `Page`를 `AppShell`(스킵링크·nav·상단바)과 `Page`(제목·콘텐츠 열)로 나눈다.

**R1이 납득 불가면 이 ADR을 「기각」으로 닫고 `wouter`로 간다.** 그 경우에도 이 문서는 남긴다 — 왜 안 갔는지가 기록이다.

### R1 측정에서 드러난 것 — 라우터 탓이 아닌 몫이 있었다

첫 측정은 **99,074 B**(한도 초과)였고 그대로면 기각 사유였다. 원인을 보니 라우터만이 아니었다 —
**Base UI(약 11 kB)가 초기 청크에 남아 있었다.** 쓰는 곳은 스타일가이드 하나뿐인데도.

`package.json` 에 `sideEffects` 선언이 없어 Rollup 이 앱의 모든 모듈을 「부작용 있음」으로 가정했고,
그래서 `shared/ui/index.ts` **배럴이 re-export 하는 것 전부**가 배럴을 import 한 청크로 끌려왔다.
`"sideEffects": ["*.css"]` 를 선언하자 Base UI 가 제 청크(스타일가이드)로 옮겨갔다:

| | 초기 청크 | 스타일가이드 청크 |
|---|---|---|
| 선언 전 | 99,074 | 5,820 |
| 선언 후 | **88,847** | 17,090 |

**이 결함은 코드 스플리팅이 들어와야 비로소 드러난다** — 청크가 하나뿐일 땐 무엇이 어디 있든 같은 값이었다.
라우터 도입이 만든 문제가 아니라, 라우터 도입이 **찾아낸** 문제다.

## 결과

**쉬워지는 것**
- URL이 화면 상태의 단일 출처가 된다 — 공유·뒤로가기·새로고침이 그냥 된다
- 오타난 링크와 잘못된 파라미터를 **컴파일러가** 잡는다
- S3의 3탭, S6의 슬라이더 상태를 URL에 올릴 도구가 생긴다(`validateSearch`)
- 화면이 늘어도 초기 청크가 함께 늘지 않는다(분할이 기본값이 되므로)

**어려워지는 것**
- 초기 JS가 늘고 **폰트 시작이 밀린다** — 분할로 상쇄하되 R7로 확인한다
- 번들 예산 한도를 올려야 한다. **측정값과 함께** 올린다(§게이트 규범)
- 배울 개념이 늘어난다(라우트 트리·타입 등록·검색 검증) — 2인 팀에 대한 실제 비용이다
- 런타임 의존이 4개 따라온다(`@tanstack/router-core` · `@tanstack/history` · `@tanstack/react-store` · `isbot`)

**뒤집으려면**
