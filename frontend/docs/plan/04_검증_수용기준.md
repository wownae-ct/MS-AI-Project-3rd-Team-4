# 04. 검증 계획 — 테스트 자산과 수용 기준 (§7)

설계서 §7의 검증 전략을 **준비해야 할 테스트 자산과 절차**로 변환한다. 테스트 작성 관례는 [guides/testing.md](../guides/testing.md) 참조.
배치 원칙: 대상 파일 옆 `*.test.ts(x)`.

## §1. 골든 바이트 벡터 (§3.5 · §7.1 — M1)

`shared/protocol/golden-vectors.ts`에 상수로 둔다. 생성 절차:

1. 대표 헤더 메타(seq·set_index·window_index·t_offset_ms·flags 조합 3~4종)를 정해 `encodeHeader`로 인코드.
2. 결과 24바이트의 16진 덤프를 **손으로 검산**(리틀엔디언·§3.2 오프셋 표 대조)한 뒤 상수로 고정.
3. 이후 테스트는 "코덱 출력 == 골든 상수" 비교.

> **재발 방지 — 순환 참조 금지**: 코덱이 회귀하면 골든 벡터가 기준이다. **코덱 자신의 출력을 근거로 골든을 갱신하지 않는다** — 갱신은 §3.2 표를 다시 손으로 검산했을 때만.

거부 벡터도 함께 상수화한다: 잘못된 magic · byteLength 불일치 · payload_length 등식 위반 · 빅엔디안 기록 · 상한 초과 — 각각 **폐기 + 카운터 증가, 예외 불방출**(§3.5)을 검증한다.

## §2. MockWebSocket 시나리오 (§7.2 — M2)

close 코드·지연·무응답 auth를 주입할 수 있는 MockWebSocket을 만들고, 아래를 전건 자동화한다 (`vi.useFakeTimers` 전제):

| # | 시나리오 | 기대 |
|---|---|---|
| S1 | AUTH_TIMEOUT · RESUME_TIMEOUT 발화 | 정확한 전이. RESUME은 재시도 소진 후에만 RESYNC_FAILED |
| S2 | 1006 수신, intentionalClose=false / true | 백오프 재접속 / 재접속 없음 |
| S3 | 4003 수신 | FAILED 잔류, 재시도 0회 |
| S4 | CONNECTING 진입 후 1000 종료 | 플래그 리셋 확인 — 재접속 대상 |
| S5 | offline→online · pageshow(persisted) | attempt 리셋 + 즉시 재연결 (백오프 미경유) |
| S6 | resume `rejected` 수신 | RESYNC_FAILED → 신규 세션 |
| S7 | 연속 티켓 실패 / 네트워크성 실패 (각 5회) | FAILED / FAILED 아님(수동 버튼만) — 두 카운터는 별개다 |
| S8 | hidden 중 유예 초과 close 후 | hidden 중 재연결 시도 0회 (§7.5 P0) |
| S9 | 하트비트 1차 미스 | 즉시 재-ping (고정 주기 아님) · 최악 감지 시간 내 |

임계·횟수의 규범값은 「하트비트」·「백오프」·「핸드셰이크 타임아웃」·「티켓·epoch」·「종료 코드」 (설계서 §2).

## §3. 룰 엔진·랜드마커 회귀 (§7.3 — M4, **G-3 확정 후**)

- **사전 녹화 랜드마크 픽스처**: 대표 동작 영상에서 추출한 33랜드마크 시퀀스 JSON. MediaPipe를 목킹하고 픽스처 입력 → 룰 판정 **결정론** 검증.
- tasks-vision 업그레이드 시: 고정 입력 세트에서 CANON19 정규 좌표 편차 허용치 이내 확인 후에만 락파일 갱신 (§7.3).
- 픽스처 제작은 G-3(CANON19 매핑 확정) 이후 — 매핑 교체 시 재생성이 필요하므로 **선제작 금지**.

## §4. 성능 스모크 (§7.4 — M5)

- Playwright 합성 30초 세션: 가짜 카메라(`--use-fake-device-for-media-stream` + y4m) → 프레임 드롭률·롱태스크(rAF 실측 + LoAF) 임계 검사.
- CI 임계 초과 시 빌드 실패 — CI 반영은 담당자 협의 ([05 문서](05_리스크_오픈이슈.md) I-2).

## §5. rule_params 스냅샷 절차 (§4.5.1 — 준비물)

1. 백엔드 `movement_fault_code.rule_params` 스키마 확정 대기 (현재 501 — 타입을 지어내지 않는다).
2. 확정 즉시: 기준 스냅샷 JSON을 번들 동봉 + SHA-256 → `DEFAULT_RULE_PARAMS_HASH` 상수.
3. 테스트: REST 5xx 강제 주입 → 번들 기본값으로 판정 지속 + `config_source: 'bundled_default'` 기록 + "코칭 기본값" 배너 표시 (§7.5 P0 — **조용한 비활성화 금지**).
