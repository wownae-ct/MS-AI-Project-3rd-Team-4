**팀 공유 실행 기획** 문서 모음이다. 규범이 아니라 실행 계획이다 — 충돌 시 항상 **설계서 v2.1 본문 > 부록 > 이 문서** 순으로 우선한다.

- 작성일: 2026-08-17 · 근거: 설계서 v2.1 전수 분석 + 외부 공식 문서 팩트체크 + Azure 실환경 실측 (원자료는 아래 "출처" 참조)
- 이 폴더는 커밋되는 **팀 공유 문서**다 (`frontend/docs/` 예외 규칙 — 상위 [README](../README.md) 참조). 시크릿·개인 메모 금지.
- **수치 규격을 여기 다시 적지 않는다** — 타이머·프로토콜 상수는 「규격 이름」과 설계서 절 번호로만 참조한다.
  (패키지 버전은 설계서 §1의 스택 확정값이므로 예외적으로 명기한다.)

## 운영 원칙

1. **작업 범위 규칙 최우선** — `package.json`·`tsconfig*`·`vite.config.ts` 수정, 의존성 추가, 디렉토리 이관은 전부 **명시적 승인 후에만** 실행한다.
2. 설계서 ↔ 코드 차이는 임의로 고치지 않고 [02 문서](02_격차분석.md)에 기록·보고한다.
3. CI(`frontend-ci.yml`)·인프라는 담당자 영역 — 프론트 코드에서 수정하지 않고 [05 문서](05_리스크_오픈이슈.md)에 요청 사항만 기록한다.
4. 갱신 책임: 게이트·이슈 상태가 바뀌면 **바뀐 PR/시점에 이 폴더도 함께 갱신**한다 (문서 부패 방지 — 상위 README 3원칙).
