# 08. Claude Code 플랜 모드 · 서브에이전트 연동 규칙

Claude Code로 이 저장소를 작업할 때 **계획(plan) 단계가 이 폴더(frontend/docs/plan)와 어떻게 맞물리는지**의 운영 규칙.
근거: Claude Code 공식 문서(2026-08-17 조사 — Subagents·Permission modes·Common workflows), 부록 A.

## §1. 왜 규칙이 필요한가 — 핵심 사실 1건

> **공식 문서 명시**: 플랜 모드의 리서치를 대행하는 내장 **Plan 서브에이전트(및 Explore)는
> `CLAUDE.md`와 세션 git status를 로드하지 않는다** (탐색 비용 절감 목적 — 다른 서브에이전트는 로드함).

이 저장소의 로컬 규범 요약(`.claude/CLAUDE.md`)은 gitignore 대상이기도 하다. 따라서 **계획 단계의 리서치가
규범·현황을 놓치지 않게 하는 유일한 안전망은 커밋되는 이 폴더**다 — 특히 [06_실행설계플랜](06_실행설계플랜.md).
이것이 06을 "실행 기준 단일 문서"로 유지하는 이유이자(D-4), 상태 변동을 즉시 06에 반영하는 이유다.

## §2. 플랜 모드 사용 규칙 (팀 공통)

| 동작 | 방법 |
|---|---|
| 진입 | `Shift+Tab`(상태 표시줄 `⏸ plan mode on`) · 단발 프롬프트는 `/plan` 접두 · CLI는 `claude --permission-mode plan` |
| 승인 | 플랜 제시 후 3택 — ① 승인+auto 모드 ② 승인+수동 편집 승인 ③ 계속 계획. **승인 시 플랜 모드가 풀리고 편집이 시작**된다 |
| 플랜 직접 수정 | 승인 프롬프트에서 `Ctrl+G` — 기본 편집기로 플랜을 고친 뒤 진행 |
| 이탈 | `Shift+Tab` 재입력 (미승인 이탈) |

**이 저장소의 추가 규칙 3건**

1. **플랜 세션의 첫 프롬프트에 `@frontend/docs/plan/06_실행설계플랜.md`를 명시 참조**한다.
   `@` 참조는 파일 내용을 직접 컨텍스트에 싣기 때문에, Plan 서브에이전트가 CLAUDE.md를 건너뛰는 공백을 메운다.
   규범 상세가 필요한 계획이면 해당 영역 문서(architecture/·plan/02~05)도 함께 참조한다.
2. **플랜 모드를 "읽기 전용 보장"으로 오해하지 않는다** — 기본 설정(`useAutoModeDuringPlan` on)에서는
   분류기가 승인한 셸 명령이 플랜 중에도 실행된다. 상태를 바꾸면 안 되는 조사라면 명령 실행을 지시하지 않는다.
3. **게이트에 걸린 작업의 계획은 계획으로 끝낸다** — G-3·G-4 미확정 영역(M2·M3 본구현)은 플랜 승인까지만 하고,
   구현 착수는 [01](01_전제와_착수게이트.md)의 게이트 해소 후로 미룬다.

## §3. 승인된 플랜의 수명주기 (산출물 보존 기준)

Claude Code의 플랜 자체는 세션 산출물이라 **저장소에 남지 않는다**. 다음 기준으로 보존을 판단한다.

| 플랜의 성격 | 처리 |
|---|---|
| 일회성 작업(버그 수정, 소규모 리팩토링) | 보존 불필요 — 결과 커밋이 기록이다 |
| **마일스톤·구조에 영향** (새 모듈 설계, 순서 변경, 게이트 대응) | 승인 직후 **06에 흡수** — 해당 절 갱신 + 개정 이력 1행. 06과 어긋난 플랜은 실행 전에 06을 먼저 고친다 |
| 결정을 동반 (승인 필요 항목 발생) | 06 §9 결정 표에 **D-N으로 추가**하고 회신을 받는다 |
| 외부 의존 발생 | [07_외부요청문](07_외부요청문.md)에 요청 초안 추가 |

원칙: **"승인된 플랜 ↔ 06"의 이원화를 만들지 않는다.** 06이 항상 최신 승인 상태를 반영한다.

## §4. 서브에이전트 운영 (이 저장소 기준)

로컬 `.claude/agents/`(gitignore — 개인 설정)에 정의된 검토 에이전트와 내장 에이전트의 용도 구분:

| 용도 | 사용 | 비고 |
|---|---|---|
| 계획 전 코드베이스 탐색 | 내장 **Plan**(플랜 모드 자동) · **Explore** | CLAUDE.md 미로드 — §2 규칙 1로 보완 |
| 규범 위반 검토 | 로컬 `spec-reviewer` (읽기 전용) | 설계서 대조 전수 검토 — 06 v1.7 감사에 사용된 방식 |
| 성능·접근성 감사 | 로컬 `a11y-perf-auditor` (읽기 전용) | M4 UI·M5 계측 후 사용 |

커스텀 플래닝 에이전트가 필요하면 공식 frontmatter 필드로 읽기 전용을 강제한다
(`tools: Read, Glob, Grep` 또는 `permissionMode: plan`, 필요 시 `skills:`로 도메인 스킬 프리로드).
정의 파일은 로컬 전용이므로 **팀 공유가 필요한 정의는 이 문서에 스니펫으로 남긴다.**

## §5. 프로젝트 기본값 (선택)

계획 우선 문화를 강제하고 싶으면 각자 로컬 `.claude/settings.json`에:

```json
{ "permissions": { "defaultMode": "plan" } }
```

이 저장소는 `.claude/`가 gitignore라 **프로젝트 강제가 아니라 개인 선택**이다 — 적용 여부는 각자 판단.
(VS Code 확장은 프로젝트 설정을 읽지 않으므로 `claudeCode.initialPermissionMode`를 사용자 설정에서 지정.)
