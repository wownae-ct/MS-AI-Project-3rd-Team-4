## §3. 재발 방지 원칙 (준비 단계에서 확인된 함정 포함)

1. **규범 충돌 시 구현하지 않고 차이 보고** — 설계서 v2.1 본문 > 부록 > 검토 보고서. 확정 전제 3건을 뒤집는 제안은 개정 절차(부록 C.2) 안내.
2. **SSOT 유지** — 수치 규격은 한 곳(규범)에만. 문서·코드에 값을 복제하면 개정 시 불일치가 재생산된다. 코드에서는 상수 선언 + 절 번호 주석.
3. **골든 벡터 순환 참조 금지** — 코덱 출력으로 골든을 갱신하지 않는다 ([04 문서](04_검증_수용기준.md) §1).
4. **정확 버전 고정 함정** — `npm i pkg@x.y.z`는 `^`가 붙어 기록된다. 확정 버전은 반드시 `-E` ([03 문서](03_적용로드맵.md) §1-4).
5. **gitignore 부정 패턴 함정** — 부모 디렉토리가 제외되면 하위 재포함(`!`)이 무시된다. `frontend/docs/` 예외는 디렉토리 패턴 자체를 부정해 회피했다 — 이 구조를 임의로 재편하지 않는다.
6. **구계약 잔재 참조 금지** — wave0 계약(구 WS 카탈로그)은 참고용 이력일 뿐이다. 새 코드·문서가 그것을 인용하면 I-1 이중화가 재생산된다.
7. **브라우저 자동 동작 의존 금지** — 예: Chrome 149의 bfcache-WS 자동 절단. 국내 사용자 약 30%가 버전 지연 Chromium — 명시적 close(§5.1)가 규범이다.
8. **인프라·CI 변경 요청에는 "설계서 영향 절"을 명기**해 담당자에게 전달한다.

## §4. 에스컬레이션 경로

- 프론트 코드로 해소 불가한 항목(I-2·I-3·I-8·I-9)은 담당자 요청 후 **이 문서에 요청 일자·응답을 기록**한다.
- 게이트 차단이 임박하면(예: M2 착수 예정인데 G-4 미합의) 마일스톤 경계 회의에서 우선 안건으로 올린다.
