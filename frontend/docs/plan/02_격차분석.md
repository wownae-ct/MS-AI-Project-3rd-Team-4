## B. 소스 코드 (해소: M1 이관 후 M2~M4 구현)

### B-1. `src/ws/client.ts` — §2·§3 전면 미충족 (M2에서 **재작성**)

현재 `SessionSocket`은 뼈대 수준이며 다음이 전부 부재:

- 8상태 머신(§2.3) · `intentionalClose` 3규칙(§2.3.2) · 백오프/attempt(「백오프」)
- 티켓 `auth` 핸드셰이크 · `resume(lastRevision)` · 앱 레벨 ping/pong(「하트비트」)
- `binaryType = 'arraybuffer'` 설정(§3.5) · `onclose`/`onerror` 핸들러
- `onmessage`의 `JSON.parse` 예외 처리 — §3.5 "무성 행(소켓 OPEN인데 처리 정지)" 금지 규정 위반 상태
- **근본 원인 — 메시지 카탈로그가 구계약**: 파일 주석·README가 wave0 계약(`session.hello`·`pose.chunk` 등, 10Hz) 기준. 규범은 §3.1 `EnvelopeType` 14종(30fps·2윈도우/s). 이 이중화가 **게이트 G-4**의 뿌리다 ([01 문서](01_전제와_착수게이트.md))
- WS URL이 `/ws/v1/sessions/{id}` 경로 파라미터 방식 — §2.1.1 "session_id는 인증된 연결 컨텍스트에서 서버가 주입" 원칙과 재정렬 필요 (G-4 협의에 포함, [05 문서](05_리스크_오픈이슈.md) I-6)

### B-2. `src/api/client.ts` — §2.2 BFF 전제 미충족 (M2 병행)

- `credentials: "include"` 없음 — BFF HttpOnly 쿠키 전제(P0)와 불일치
- 요청 타임아웃(AbortController) · 401 재시도(토큰 회전) 경로 없음
- 응답 타입 `unknown` 유지는 **규범 준수 상태** — 백엔드가 501 스텁이라 Pydantic 확정 전 타입을 지어내지 않는다

### B-3. `src/pose` · `src/rules` · `src/ui` — README만 존재 (M3·M4)

- CANON19 변환·Worker 파이프라인·윈도우 조립(§4) 전부 미구현
- T1 룰 엔진·rule_params 확보 경로(§4.5) · Wake Lock(§5.3) · entry-guard(§6.2.1) · 오디오 큐(§4.5.2) · 오버레이(§4.2) 미구현
- ⚠️ 기존 README의 성능 수치는 구판(v0.7) 기준 — v2.1 SLO(「추론 SLO」·「T1 판정 SLO」, §6.3·§4.5)와 다르다. **이관 시 README 갱신 대상**

### B-4. 디렉토리 구조 — FSD 미이관 (M1)

- 현재 `src/{pose,rules,api,ws,ui}` + `App.tsx`/`main.tsx` 평면 구조
- §6.1 신설 슬라이스 전부 미생성: `pages/` · `entities/` · `features/entry-guard` · `shared/protocol` · `shared/workers`
- 목표 구조·이관 매핑·import 규칙은 [architecture/directory-structure.md](../architecture/directory-structure.md), 실행 순서는 [03 문서](03_적용로드맵.md)
