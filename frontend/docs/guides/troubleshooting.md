# 트러블슈팅 — 증상 → 원인 → 절차

구현·디버깅 중 만날 증상의 1차 진단표. 각 항목의 근본 원인은 설계서가 이미 규정한 함정이다 —
"고치기 전에 어느 규범에 걸린 것인지"부터 확인한다. 새 함정을 발견하면 이 표에 추가한다.

## WebSocket

| 증상 | 유력 원인 | 확인·조치 |
|---|---|---|
| 소켓은 OPEN인데 메시지 처리가 멈춤 (무성 행) | `onmessage` 안에서 예외 유출 — 수신 가드 미적용 | 가드 실패는 폐기+카운터 (P0-12). `JSON.parse` try/catch 여부, 카운터 증가 여부 확인 |
| 백그라운드 갔다 오면 연결이 안 살아남 | 복귀 시 `readyState`만 믿고 재검증 생략 | ping 1회 왕복 재검증 경로 확인 (「라이프사이클 타이머」) — OPEN은 거짓말한다 |
| 의도적으로 닫았는데 재접속됨 | 1005/1006 분기에서 `intentionalClose` 미확인 | P0-5② — 1000뿐 아니라 1005/1006 분기에도 플래그 검사 |
| 재연결이 폭주 (플래핑) | attempt를 접속 즉시 리셋 | 리셋은 CONNECTED 연속 유지 후에만 (「백오프」) |
| `close(3001)` 이 InvalidAccessError | 3000번대는 IANA 라이브러리 범위 | 클라이언트는 1000 또는 4000번대만 (「종료 코드」) |
| 수십 초 유휴 후 서버가 끊음 | 하트비트 주기 > 인프라 유휴 타임아웃 | 주기를 늘렸는지 확인 — 「하트비트」는 늘리면 안 되는 값 |
| 바이너리가 Blob으로 옴 | `binaryType = 'arraybuffer'` 미설정 | CONNECTING 진입 직후 설정 (기본값이 blob) |
| 재연결마다 좌표 시간축이 튐 | t_offset 원점을 재연결마다 재바인딩 | 재바인딩은 session_id 변경 시만 (「t_offset_ms」) |

## 카메라·Worker·파이프라인

| 증상 | 유력 원인 | 확인·조치 |
|---|---|---|
| 수 분 뒤 캡처가 조용히 멈춤 | 프레임 close 누수 — GPU/디코더 고갈 | P0-8: 경로별 정확 1회 close. 개발 빌드 미해제 카운터 확인 |
| 화면은 나오는데 랜드마크 정지 | 카메라 스톨 (track mute/ended) | 워치독·track 이벤트 구독 여부 (§4.1.2). 절차: 안내 → getUserMedia 1회 재시도 → session_pause |
| Worker 응답 지연·무응답 | GPU 컨텍스트 유실 등 | 헬스 경로 확인: 재생성(상한 있음) → 메인 강등. `webglcontextlost` → CPU delegate (「Worker 타이머」) |
| 추론이 유난히 느린 기기 | GPU delegate 실패로 CPU 폴백 중 | 리스크 R-4 — 캡처 주기 하향 동작 확인, 계측치 확인 |
| WASM/모델 로드 실패 (프로덕션만) | SWA mimeTypes 미설정 or CDN 경로 잔존 | `.wasm`/`.task` MIME 확인 (deployment.md §3), self-host 경로 확인 (P0-10) |
| 오디오 큐가 안 나옴 | AudioContext 언락 실패 | 세션 시작 제스처에서 `resume()` — `state !== 'running'`이면 시작 차단이 정상 동작 (§4.5.2) |

## 세션·환경

| 증상 | 유력 원인 | 확인·조치 |
|---|---|---|
| 운동 중 화면이 꺼짐 | Wake Lock 미획득/자동 해제 후 미재획득 | `release` 이벤트 구독 + visible 복귀 재획득 확인 (P0-15). hidden 중 `request()`는 원래 거부됨 |
| 카카오톡에서 카메라가 안 됨 | 인앱 웹뷰 — 복구 불가가 정상 | 재시도 루프 만들지 말 것 (P0-16). entry-guard 유도 화면이 뜨는지 확인 |
| 시크릿 모드에서 로그인 실패 | 크로스사이트 쿠키 차단 (G-2 도메인 미확보 상태의 알려진 제약) | §2.2.1 안내 문구 표출 확인 — 환경별 쿠키 분기를 만들지 않는다 |
| staging에서 API가 prod로 감 (또는 그 역) | 빌드타임 치환 — 잘못된 산출물 배포 | 산출물의 `VITE_API_BASE` 확인. 런타임 스위칭으로 "고치지" 말 것 (§1) |
| 코칭(fault 판정)이 조용히 안 나옴 | rule_params 확보 실패의 무성 처리 | P0-13: 3단 강등 + 배너가 정상 경로 — 배너 없이 비활성이면 버그 |

## 디버깅 원칙

1. 증상을 재현하는 **최소 시나리오**를 먼저 만든다 (MockWebSocket·픽스처 활용 — testing.md).
2. 관측 지표(§6.5 9종)와 가드 카운터를 먼저 본다 — 로그보다 카운터가 먼저 거짓말을 걸러낸다.
3. 수정이 규범(P0 17건)과 충돌하는 방향이면 멈추고 보고 — "동작하게 만드는" 수정이 규범 위반이면 그것은 수정이 아니라 새 버그다.
