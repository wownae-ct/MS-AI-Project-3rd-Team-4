# 룰 엔진·코칭 — T1 판정·rule_params·오디오 큐

> 근거: 설계서 v2.1 §4.5. 구현 규칙의 SSOT는 `.claude/skills/t1-rule-engine`,
> 수치는 CLAUDE.md §4 (「T1 판정 SLO」·「모델·오디오」).

## 1. 판정의 2계층 — 잠정과 권위

```
CANON19 월드 좌표 ──► T1 룰 엔진 (브라우저, 순수 함수) ──► 잠정 fault → 즉시 큐/자막
                                                              │
서버 판정 verdict (verdict_source: rules/tcn/hybrid) ─────────┴──► 서버 권위로 정정
```

- **T1 판정은 잠정 결과다.** 서버 `verdict` 도착 시 서버가 항상 이긴다 (§4.5·§2.1).
  UI는 이 정정을 자연스럽게 흡수하도록 설계한다 (잠정 표시를 단정적으로 그리지 않는다).
- T1의 존재 이유는 **지연 은폐**: 서버 왕복을 기다리지 않고 즉각 피드백을 주되, 정합은 서버가 보장한다.
- 룰 엔진은 **순수 함수**로 유지 (`features/rules`) — 입력은 CANON19 월드 채널, 출력은 fault 후보. 부수효과 없음 → 픽스처 기반 결정론 테스트 가능 (§7.3).

## 2. rule_params — 임계값은 서버에서 온다 (P0-13, §4.5.1)

- **임계값 하드코딩 금지.** 세션 시작 시 REST로 `movement_fault_code.rule_params` 수신·캐시 + 스냅샷 해시 기록.
- 확보 실패는 3단 강등: **번들 기본 → IndexedDB 캐시 → "코칭 비활성" 배너**.
  **조용한 비활성화 금지** — 사용자는 코칭이 없는 이유를 알아야 한다.
- **세션 도중 파라미터 갱신 금지** — 세트 중간에 판정 기준이 바뀌면 사용자 신뢰가 무너진다.
- 어떤 파라미터로 판정했는지(`config_source`·해시)를 텔레메트리에 남긴다 — 서버 판정과 어긋날 때 원인 추적의 열쇠.
- 현재 백엔드는 501 스텁 — 스키마 확정 전 타입 지어내기 금지(`unknown` 유지). 번들 스냅샷 생성 절차는 `docs/plan/06_테스트_검증준비.md` §5.

## 3. 오디오 큐 (§4.5.2)

- **언락**: AudioContext는 세션 시작 제스처 핸들러에서 `resume()`. `state !== 'running'`이면 세션 시작 차단 —
  "소리 없는 코칭 세션"을 시작 후에 발견하는 것보다 시작을 막는 것이 낫다.
- **디바운스 + 우선순위**: 최소 간격 디바운스, 우선순위는 안전 > 폼 > 격려 (「모델·오디오」).
  높은 우선순위는 낮은 것을 선점할 수 있으나 그 역은 없다.
- 사전 녹음 스프라이트 사용 (TTS 아님) — 지연·품질·오프라인 안정성. 자막 병행 (접근성 + 음소거 환경).

## 4. 함정 목록

- 룰 판정에 **정규화 좌표(x_norm/y_norm)를 쓰지 않는다** — 각도 계산은 월드 좌표(m) 채널. 정규화 좌표는 화면 비율에 종속된다.
- visibility 낮은 관절이 낀 각도는 판정 보류가 원칙 — 가려진 관절로 fault를 선언하면 오탐 폭주.
- T1 SLO는 메인 스레드 예산의 일부다 — Worker 추론 SLO와 비교하는 것은 범주 오류 (「T1 판정 SLO」 주석).
