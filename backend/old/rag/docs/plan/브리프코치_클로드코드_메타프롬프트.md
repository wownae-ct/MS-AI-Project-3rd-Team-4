> 이 문서 전체를 Claude Code 첫 메시지로 붙여넣으세요. 아래 "참고 문서"에 나열된 파일들은 실제로 리포지토리에 넣어둔 뒤 시작해야 합니다.

## 0. 프로젝트 컨텍스트

**브리프코치(BriefCoach)** — 개발자·IT·전문직을 위한 AI 화법 트레이너. 기존 "크로스핏 폼 코치" 프로젝트에서 주제만 피벗했고, 인프라(Azure/FastAPI/PostgreSQL+pgvector/CI-CD)는 그대로 재사용한다. 실시간 웹캠·포즈인식·룰엔진·TCN은 전부 제외하고, "제한시간 답변 → STT/지표추출 → 코칭 에이전트 → 근거검증 에이전트(RAG) → 비동기 리포트" 구조로 새로 설계했다.

- `기술설계서.md` — 기술스택, 서비스흐름도(S0~S5), 컴포넌트/시퀀스 다이어그램, LangGraph 채택 근거
- `API_명세서.md` — REST + SSE 엔드포인트 스펙
- `DB_설계서_ERD.md` — 테이블 정의서, ERD (특히 `speech_guide_doc`, `speech_guide_chunk`, `guardrail_check`)
- `RAG_설계서.md` — 코퍼스 소스, 청킹 전략, 임베딩 모델, 검색·가드레일 체인
- `RAG_코퍼스_저작권검토.md` — 코퍼스 소스별 라이선스 판정

## 2. 오늘의 작업 범위 (이번 세션에서 할 일)

**RAG 청킹 → 임베딩 → 적재 → 검색 파이프라인만 구현한다.** 코칭 에이전트·근거검증 에이전트(LangGraph 그래프)는 이번 스코프 아님 — 그건 이 파이프라인이 끝난 뒤 별도 세션에서 진행한다.

### 2-1. DB 마이그레이션
- `DB_설계서_ERD.md`의 `speech_guide_doc`, `speech_guide_chunk` 테이블을 SQL 마이그레이션으로 작성 (`speech_guide_chunk.embedding`은 `vector(1536)`)
- 기존 프로젝트 컨벤션대로 번호 붙인 순수 SQL 파일 + 러너 방식 사용 (기존 `scripts/migrate.py` 있으면 재사용, 없으면 있는 패턴 찾아서 따를 것)
- pgvector HNSW 인덱스 생성

### 2-2. 코퍼스 적재 스크립트
- `RAG_코퍼스_v1_*.md` 파일들을 파싱해서 `DOC-NN [카테고리] 제목 / 출처 / 본문` 구조를 추출
- 각 DOC를 `speech_guide_doc`에 삽입 (title=DOC 제목, source_url=출처가 URL이면 채우고 아니면 NULL, body_text=본문)
- 청킹: 300~500자, 문단 우선 분할 후 문장 경계에서 추가 분할 (문장 중간 절단 금지) — `RAG_설계서.md` §3 그대로
- 대부분 DOC은 이미 300~500자라 청크 1개로 끝날 것, 넘는 것만 분할

### 2-3. 임베딩
- Azure OpenAI `text-embedding-3-small`로 각 청크 임베딩 생성
- API 키/엔드포인트는 하드코딩 금지 — 기존 프로젝트의 환경변수/설정 관리 방식(runtime_config 또는 .env 패턴) 그대로 따를 것. **기존 패턴을 찾아서 재사용하고, 임의로 새 설정 방식을 만들지 마라.**
- `speech_guide_chunk`에 적재

### 2-4. 검색 함수
- `search_speech_guide(query: str, k: int) -> list[Chunk]` — pgvector HNSW top-k 임베딩 검색 함수 구현
- 이번 스코프에선 tag_filter 등 추가 경로 없음, 순수 임베딩 검색 단일 경로만 (RAG_설계서.md §5 참고)

### 2-5. 검증
- 코퍼스 30~50건이 전부 청크로 잘 쪼개졌는지, 임베딩이 다 채워졌는지 카운트 확인
- 대표 쿼리 5개(예: "두괄식이 뭐야", "STAR 기법 예시 보여줘", "코드 리뷰할 때 어떻게 말해야 해") 로 `search_speech_guide` 호출해서 관련 청크가 top-k에 나오는지 수동 확인

## 3. 기술 스택 (기존 인프라 재사용 — 재설계 금지)

| 항목 | 값 |
|---|---|
| 언어/프레임워크 | Python, FastAPI |
| DB | PostgreSQL Flexible Server + pgvector |
| 임베딩 모델 | Azure OpenAI text-embedding-3-small (1536차원) |
| 배포 | 기존 AKS (또는 Container Apps — 리포지토리에 이미 있는 쪽 그대로) |

## 4. 코딩 컨벤션 (기존 프로젝트와 동일)

- No hardcoding — 값은 상수/설정/env로 관리
- 함수 ≤ 50줄, 파일 ≤ 800줄
- 기존 패턴이 있으면 그대로 따르고, 임의로 새 추상화를 만들지 않는다
- 마이그레이션은 번호 붙인 순수 SQL + 러너 (Alembic 등 새 도구 도입 금지 — 원 프로젝트가 의도적으로 스코프컷한 부분)
