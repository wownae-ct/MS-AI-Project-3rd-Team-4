# 시크릿 회전 절차 — Postgres 관리자 비밀번호

## 왜 이 문서가 있나

2026-08-13에 Postgres 관리자 비밀번호가 문서에 평문으로 커밋됐다. `595a12f`가 파일에서 지웠지만
**git 히스토리에는 그대로 남아 있다.** 그런데 `README.md`에는 "히스토리까지 재작성해서 지웠다"고
적혀 있어서, 팀이 이미 해결됐다고 믿는 상태였다(2026-08-19 정정).

파일에서 지우는 것과 히스토리에서 없애는 것은 다르다. 그리고 **히스토리에서 지우는 것보다
값을 바꿔서 무의미하게 만드는 쪽(회전)이 거의 항상 낫다.**

## 확인된 노출 범위 (2026-08-19)

| 항목 | 상태 |
| --- | --- |
| 현재 워킹트리 / 각 브랜치 tip | ✅ 깨끗 |
| git 히스토리 | ❌ **11개 커밋에 잔존** |
| 노출 브랜치 | `main`, `backend`, `feature/backend` — 세 브랜치 모두의 조상 (GitHub compare API 확인) |
| 저장소 공개 여부 | private (외부 노출 아님, 접근자는 팀원) |

> 조사 방법: 값 자체는 출력하지 않고 존재 여부만 대조했다. 처음엔 영문 키워드
> (`password|secret|key`)로만 grep해서 **놓쳤다** — 실제 문장이 한글 "비밀번호"였기 때문이다.
> 시크릿 탐지를 짤 때 이 저장소는 한글 문맥을 반드시 포함해야 한다.

## 지금이 회전 적기인 이유

**현재 이 비밀번호를 참조하는 실행 코드가 없다.**

- `infra/k8s/base/backend/secretproviderclass.yaml`의 `pg-connstr`은 "backend DB 코드가 아직
  없어서" 의도적으로 Key Vault 목록에서 제외돼 있다(`fdc0d1b`).
- `backend/app/db/__init__.py`는 아직 도커스트링만 있는 껍데기다.
- Key Vault에도 pg 관련 시크릿이 없다.

즉 지금 바꾸면 **깨질 것이 없다.** 앱이 DB에 붙기 시작하면 회전 비용이 급격히 커진다.

## 회전 절차 (3곳)

값을 바꾸면 옛 값은 히스토리에 남아도 아무 데도 접속할 수 없게 된다.

```bash
# 1) Azure의 실제 비밀번호 변경
#    서버 이름 규칙: ${NAME_PREFIX}-pg  (bicep/modules/postgres.bicep:16) → team4hc-pg
az postgres flexible-server update \
  --resource-group "<AZURE_RG>" \
  --name "<NAME_PREFIX>-pg" \
  --admin-password "<새 비밀번호>"

# 2) GitHub Secret 갱신 — infra-deploy.yml:30이 Bicep에 주입한다
gh secret set POSTGRES_ADMIN_PASSWORD

# 3) 로컬 infra/.env 갱신 — scripts/deploy-infra.sh:24가 읽는다
#    (infra/.env는 git 비추적)
```

관리자 계정명(`POSTGRES_ADMIN_LOGIN`)은 바꾸지 않아도 된다 — 유출된 건 비밀번호다.

### 확인

```bash
# 새 비밀번호로 접속되는지
PGPASSWORD='<새 비밀번호>' psql -h "<NAME_PREFIX>-pg.postgres.database.azure.com" \
  -U "<POSTGRES_ADMIN_LOGIN>" -d postgres -c 'select 1'

# 다음 인프라 배포가 새 값으로 도는지 (what-if)
gh workflow run infra-deploy.yml -f whatIf=true
```

## 회전 vs 히스토리 재작성

| | 회전 (권장) | 히스토리 재작성 |
| --- | --- | --- |
| 하는 일 | 옛 값을 **무의미하게** 만든다 | 옛 값을 **삭제**한다 |
| 손대는 곳 | Azure 1 + GitHub Secret 1 + 로컬 `.env` 1 | 모든 브랜치의 커밋 SHA |
| 팀 영향 | **없음** | **전원 재클론 필수** — 브랜치 7개, 진행 중인 PR·작업 파손 |
| 소요 | 수 분 | 수 시간 + 전원 조율 |
| 남는 위험 | 옛 값이 히스토리에 남음(단, 무의미) | 없음 |

private 저장소이고 접근자가 팀원뿐이라 잔여 위험이 작다. **회전을 권장한다.**

히스토리 재작성이 꼭 필요하다고 판단되면 `git filter-repo`를 쓰되, 반드시 회전을 **먼저** 하고
(재작성 중에도 옛 값은 유효하므로) 전원 재클론 공지를 함께 진행한다.

## 재발 방지

- `.githooks/pre-commit` ⑤가 커밋 전에 gitleaks로 스테이징분을 검사한다.
  단 **gitleaks가 설치돼 있어야** 동작한다 — 미설치면 경고만 남기고 통과한다.
  설치: https://github.com/gitleaks/gitleaks/releases (리눅스/WSL은 `_linux_x64.tar.gz`)
- CI는 `.github/workflows/gitleaks.yml`이 모든 PR과 main push에서 검사한다.
- `.gitleaks.toml`의 기본 룰셋이 한글 문맥 평문을 잡는지는 **아직 미검증**이다.
  `docker run --rm -v "$PWD":/repo ghcr.io/gitleaks/gitleaks:latest git /repo --config /repo/.gitleaks.toml --redact`
  로 확인하고, 못 잡으면 한글 문맥 룰을 추가해야 한다.
- 문서에 시크릿을 적지 않는다. 값이 필요하면 "`infra/.env` 참고"라고만 쓴다.
