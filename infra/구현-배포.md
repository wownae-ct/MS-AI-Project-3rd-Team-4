# 인프라 배포 상세 (what-if 기준, 2026-08-13)

> "왜 이렇게 결정했나"는 [구현-요약.md](./구현-요약.md), "어떻게 실행하나"는 [할일.md](./할일.md) 참고.
> 이 문서는 `az deployment group what-if` 결과에 나온 실제 리소스 설정을 리소스별로 자연어로 풀어 정리한 것 —
> 나중에 "우리 Azure 환경이 정확히 뭘로 구성돼 있나" 다시 볼 때 Bicep 원문 안 읽고도 파악하기 위한 용도.
> 이름 프리픽스(`aicoach`/`team4` 등)는 `infra/.env`의 `NAME_PREFIX`에 따라 달라짐 — 아래는 예시 값 기준.

## ACR (Container Registry) — `<prefix>acr`

백엔드 Docker 이미지 저장소.

- **`adminUserEnabled: false`** — ACR의 관리자 계정(고정 아이디/비번) 로그인을 아예 꺼둠. 이미지 pull/push는
  전부 Managed Identity(AKS kubelet identity, Image Updater identity)로만 하게 강제 — 정적 자격증명이
  새어나갈 여지 자체를 없앤 보안 설정.
- **`autoGeneratedDomainNameLabelScope: NoReuse`** — 나중에 이 ACR을 지워도 같은 이름을 남이 다시 가져다
  쓸 수 없게 함(서브도메인 탈취 방지).
- **`sku.name: Basic`** — 가장 저렴한 티어(10GB 저장 한도).

**역할 할당 2개** — 둘 다 정적 토큰 없이 Managed Identity 기반:

- AKS **kubelet identity**에 `AcrPull` 부여 → 노드가 컨테이너 이미지를 실제로 내려받을 때 필요
- **Image Updater identity**에 `AcrPull` 부여 → ArgoCD가 ACR의 새 이미지 태그 목록을 조회할 때 필요
  (둘을 분리한 이유: "워크로드 identity"와 "GitOps 컨트롤러 identity"는 관심사가 달라서)

**진단 로그** — 전체 로그(`allLogs`) + 전체 메트릭을 Log Analytics로 전송(감사·트러블슈팅용).

**주간 purge 태스크** — 매주 일요일 00:00 UTC에 `backend:*` 태그 중 14일 지난 이미지를 최신 5개만 남기고
삭제(미태그 이미지도 삭제) — Basic 티어 10GB 한도를 자동으로 관리.

## AKS — `<prefix>-aks`

- **`aadProfile.enableAzureRBAC: true` / `managed: true`** — kubectl 접근을 정적 kubeconfig 토큰이 아니라
  **Azure AD 계정 기반**으로 통제. 팀원이 늘거나 빠질 때 Azure AD 권한만 조정하면 됨(kubeconfig 파일 유출
  걱정 없음).
- **`addonProfiles.azureKeyvaultSecretsProvider`** — Key Vault의 시크릿(OpenAI 키, DB 연결정보)을 파드에
  파일로 자동 마운트해주는 드라이버. `rotationPollInterval: 2m` = 2분마다 Key Vault 쪽 값이 바뀌었는지
  확인해서 자동 갱신.
- **`addonProfiles.azurepolicy: false`** — Azure Policy(리소스 배포 규칙 강제) 안 씀 — 2인 팀 단기
  프로젝트라 거버넌스 오버헤드 불필요 판단.
- **`addonProfiles.omsagent`** — Container Insights(파드/노드 모니터링)를 Log Analytics workspace로 연결.
- **노드풀 2개**: `system`(B2s, 고정 1대, `CriticalAddonsOnly` taint로 시스템 파드 전용) + `user`(D2s_v5,
  1~6대 오토스케일, 실제 앱이 여기서 돎).
- **`autoUpgradeProfile`이 둘 다 `none`/`None`** — Kubernetes 버전도, 노드 OS도 자동 업그레이드 안 함 —
  데모 도중에 예고 없이 노드가 재부팅되는 걸 방지.
- **`networkProfile.networkPolicy: none`** — 파드 간 네트워크 격리 정책 없음(워크로드가 몇 개 안 돼서 격리
  필요성 낮다고 판단).
- **`oidcIssuerProfile.enabled` + `securityProfile.workloadIdentity.enabled`** — **Workload Identity**
  활성화. 파드가 고정 비밀번호/키 없이 "나는 이 서비스어카운트다"라는 걸 Azure AD에 증명하고 임시 토큰을
  받아 Key Vault/OpenAI/Storage에 접근 — 이 프로젝트 전체를 관통하는 "정적 자격증명 대신 Managed Identity"
  원칙의 핵심.
- **`sku.tier: Free`** — 컨트롤플레인 SLA(가동률 보장) 없는 무료 티어 — 20일짜리 프로젝트엔 유료 SLA
  불필요.

## Managed Identity 2개 + Federated Credential

- **`<prefix>-backend-id`**: `staging`/`production` 네임스페이스 각각에 대해 federated credential 생성 —
  두 환경의 backend 파드가 각자 이 identity로 Azure OpenAI/Key Vault/Postgres/Storage를 인증 없이(비밀번호
  없이) 호출 가능하게 해줌.
- **`<prefix>-image-updater-id`**: `argocd` 네임스페이스의 `argocd-image-updater` 서비스어카운트 전용 —
  ACR 태그 조회할 때만 씀. `properties.issuer`가 AKS의 OIDC 발급자 URL을 참조하는데, 이게 Workload
  Identity가 "이 서비스어카운트 = 이 Azure identity"를 신뢰하는 연결고리.

## Log Analytics(`<prefix>-law`) + App Insights(`<prefix>-appi`)

- Log Analytics: `PerGB2018` 요금제, 30일 보존, **`dailyQuotaGb: 2`** — 하루 2GB 넘게 로그가 쌓이면 그
  이후 로그는 안 받음(로그 폭주로 예산 초과되는 걸 막는 안전장치).
- App Insights: 위 Log Analytics workspace 기반으로 앱 레벨 관측성(응답시간, 에러율 등) 수집.

## Static Web App — `<prefix>-swa`

- **`location: eastus2`** — 다른 리소스는 다 `koreacentral`인데 이것만 다른 리전 — SWA Free 티어가
  지원하는 리전이 제한적이라서(한국 리전 미지원).
- **`stagingEnvironmentPolicy: Enabled`** — PR 올릴 때마다 프리뷰용 별도 URL이 자동 생성됨.
- **`properties.provider: GitHub`**이지만 `repositoryUrl`/`repositoryToken`은 일부러 안 넘김 — 넘기면
  Azure가 자체 GitHub Actions 워크플로를 자동 생성해서, 이미 손으로 짜둔 `frontend-ci.yml`(빌드는 GitHub
  러너에서, SWA엔 결과물만 업로드)과 충돌하기 때문.

## what-if에 안 보이는 것: Key Vault / Postgres / Foundry(OpenAI) / Storage

이 4개는 `backendIdentityPrincipalId`(AKS가 실제로 만들어져야 나오는 값)를 파라미터로 받아서, what-if가
`NestedDeploymentShortCircuited`로 미리보기를 건너뛴다(정상 동작 — 실배포에선 의존성 순서대로 만들어짐).
이 안에 들어있는 보안 설정 요약:

- **Key Vault**: RBAC 인증(액세스 정책 방식 아님), backend Identity에 `Key Vault Secrets User`만 부여
- **Postgres**: AAD 인증 + 비밀번호 인증 병행, 관리자 비밀번호는 `infra/.env`로만 전달(git 비추적)
- **Foundry(구 Azure OpenAI)**: `disableLocalAuth: true` — API 키 완전 비활성화, Managed Identity로만 호출.
  `kind: AIServices` + `allowProjectManagement: true`로 처음부터 Foundry 리소스로 배포(Speech/Agent Service
  확장 여지)
- **Storage**: `allowBlobPublicAccess: false`, TLS 1.2 강제, 계정 키는 ml 레포 업로드용으로만 유지
  (`allowSharedKeyAccess: true`)

## 리소스 개수 참고

what-if에 보이는 15개(ACR 5 + AKS 2 + App Insights 1 + Managed Identity/Federated Credential 3 +
Log Analytics 1 + Static Web App 1 = 15) 외에, short-circuit된 4개 모듈(keyvault/postgres/openai/storage)
안의 하위 리소스까지 합치면 실제 배포 리소스 수는 이보다 훨씬 많다.
